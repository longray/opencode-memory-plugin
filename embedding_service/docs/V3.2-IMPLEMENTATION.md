## 3. Phase 2: WebSocket 重构

**目标**: 实现可靠的 WebSocket 连接（心跳、重连、ACK、DIFF、状态恢复）
**工时**: 2-3 天

### 3.1 核心组件

```
utils/websocket/
├── reliable_client.py    # 可靠连接管理
├── ack_system.py         # ACK 确认系统
├── state_recovery.py     # 状态恢复
└── persistent_queue.py   # 持久化队列
```

### 3.2 实现要点

#### 心跳机制

```python
# 30s 间隔，2 次未响应触发重连
HEARTBEAT_INTERVAL = 30.0
MAX_MISSED_PONGS = 2
```

#### 指数退避重连

```python
# 1s → 2s → 4s → 8s ... 最大 300s，最多 10 次
delay = min(base_delay * (2 ** retry_count), max_delay)
delay += random.uniform(0, 1)  # 添加抖动
```

#### ACK 确认

```python
# 5s 超时，3 次重试
ACK_TIMEOUT = 5.0
ACK_MAX_RETRIES = 3
```

#### DIFF 模式

```python
# 基于 SurrealDB LIVE SELECT DIFF
# 减少 90% 数据传输
query = f'LIVE SELECT DIFF FROM entity WHERE tenant_id = "{tenant_id}"'
```

### 3.3 验收标准

| 标准             | 值      |
| ---------------- | ------- |
| 心跳成功率       | ≥ 99%   |
| 重连时间（首次） | < 5s    |
| ACK 确认率       | > 99.9% |
| 并发连接         | ≥ 1000  |
| 消息延迟 p99     | < 100ms |

## 4. Phase 3: PrecomputeService

**目标**: 实现服务化代码分析，批处理 + 增量更新
**工时**: 2-3 天

### 4.1 核心组件

```python
class PrecomputeService:
    """代码分析预计算服务"""

    def __init__(self, batch_size=100, max_concurrent=5):
        self.batch_size = batch_size
        self.max_concurrent = max_concurrent
        self.semaphore = asyncio.Semaphore(max_concurrent)
        self.processing: Set[str] = set()  # 去重
```

### 4.2 处理流程

```
文件保存 → SHA256 指纹 → 变更检测 → tree-sitter AST
    → 符号提取 → 批量创建 Atoms → 创建 Entity
    → 创建 References → 性能记录
```

### 4.3 支持语言

| Rust       | tree-sitter-rust 0.24.x       | 完整 |

## 5. Phase 4: Meilisearch 升级

**目标**: 升级 Meilisearch Python SDK 到 0.40.x
**工时**: 1 天

### 5.1 迁移内容

| 操作     | 旧方式（httpx）                  | 新方式（SDK 0.40）               |
| -------- | -------------------------------- | -------------------------------- |
| 初始化   | `httpx.AsyncClient()`            | `Client(url, api_key)`           |
| 创建索引 | `client.post("/indexes", ...)`   | `client.create_index(uid)`       |
| 添加文档 | `client.post("/documents", ...)` | `index.add_documents(docs)`      |
| 搜索     | `client.post("/search", ...)`    | `index.search(query, options)`   |
| 等待任务 | 手动轮询                         | `client.wait_for_task(task_uid)` |

### 5.2 性能预期

| 操作               | 旧方式 | 新方式 | 提升 |
| ------------------ | ------ | ------ | ---- |
| 添加 100 文档      | 150ms  | 120ms  | 20%  |
| 搜索               | 50ms   | 45ms   | 10%  |
| 批量添加 1000 文档 | 800ms  | 600ms  | 25%  |

| 创建辅助表            | timeline, stats 等      |
| 启用 ChangeFeed 7d    | atom, entity, reference |
| 创建新索引            | 复合索引                |
| 创建事件和函数        | 自动更新 updated_at     |

### 7.2 迁移脚本

```python
# db/migrations/migrate_v2_to_v3.2.py
async def migrate():
    async with Surreal("ws://localhost:8000") as db:
        await db.signin({"user": "root", "pass": "root"})
        await db.use("opencode", "memory")

        # 1. 添加 tenant_id
        await db.query("UPDATE atom SET tenant_id = 'default' WHERE tenant_id IS NONE")
        await db.query("UPDATE entity SET tenant_id = 'default' WHERE tenant_id IS NONE")
        await db.query("UPDATE reference SET tenant_id = 'default' WHERE tenant_id IS NONE")

        # 2. 创建辅助表
        # 3. 创建索引
        # 4. 创建事件和函数
```

## 9. 回滚方案

### 9.1 代码回滚

```bash
# 回退到上一个稳定版本
git checkout v3.1.0
docker-compose down
docker-compose up -d
```

### 9.2 数据库回滚

```bash
# 从备份恢复
docker exec -i opencode-surrealdb surreal import \
  --conn http://localhost:8000 \
  --user root --pass root \
  --ns opencode --db memory \
  < /backup/pre-v3.2-backup.sql
```

### 9.3 端口回滚

如果端口迁移出现问题，可以临时启用向后兼容：

```bash
ENABLE_LEGACY_PORT=true docker-compose up -d
# 旧客户端继续使用 17999
```
