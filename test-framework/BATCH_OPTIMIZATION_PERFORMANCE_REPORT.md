### 3. 预生成策略效果显著
- **预生成阶段仅耗时 91ms**（占总时间的 98.9%）
- **50 条数据一次性批量生成**，充分利用批量 API 的优势
- **缓存机制使得后续写入几乎瞬时完成**

## 🔍 优化原理解析

### 原始版本的问题
```
每次 memory_write 调用:
  ↓ 生成 embedding
    ↓ 调用 API (网络请求 + 服务器处理)
      ↓ 等待响应 (50-300ms)
        ↓ 存储到索引

50 次写入 = 50 次 API 调用 = 50 次网络往返
```

### 批量优化版本的改进
```
阶段1 - 预生成:
  ↓ 收集所有需要生成的文本
    ↓ 批量调用 API (1 次请求包含 50 条文本)
      ↓ 一次性获取所有 embedding (90ms)
        ↓ 存入缓存

阶段2 - 写入:
  ↓ 每次 memory_write
    ↓ 直接从缓存读取 (0ms)
      ↓ 存储到索引

50 次写入 = 1 次 API 调用 + 50 次缓存读取
```

### 核心优化点

1. **批量 API 调用**
   - 利用本地嵌入服务的批量处理能力
   - 一次请求处理多条文本，分摊网络开销

2. **预生成策略**
   - 在测试开始前预先生成所有需要的 embedding
   - 避免在测试过程中实时调用 API

3. **缓存机制**
   - 使用内存缓存存储预生成的 embedding
   - 后续写入操作直接从缓存读取，几乎零延迟

4. **减少网络往返**
   - 将 50 次网络请求减少到 1 次
   - 大幅降低网络延迟对性能的影响
