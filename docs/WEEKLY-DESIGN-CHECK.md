# 每周设计符合性检查流程

> **版本**: v1.0.0  
> **日期**: 2026-04-10  
> **频率**: 每周五下午  
> **时长**: 30-60 分钟

---

## 概述

本文档定义每周设计符合性检查流程，确保开发进度与设计文档保持一致，及时发现和解决偏差。

---

## 检查时间

- **时间**: 每周五下午 15:00-16:00
- **形式**: 团队会议（线上/线下）
- **参与者**: 开发团队、架构师、项目经理

---

## 检查流程

### 1. 准备阶段（会前 10 分钟）

**负责人**: 项目经理

1. 更新 RTM 状态
2. 收集本周变更列表
3. 准备检查清单

```bash
# 自动准备脚本
npm run weekly-check:prepare
```

---

### 2. RTM 状态审查（10 分钟）

**负责人**: 技术负责人

检查 RTM 中各模块状态：

| 模块 | 检查项 | 负责人 |
|------|--------|--------|
| WebSocket | 心跳/重连/DIFF 实现进度 | @dev1 |
| PrecomputeService | 批处理/增量/关系创建进度 | @dev2 |
| Database Schema | Schema 迁移/字段添加进度 | @dev3 |
| API | 端点实现/契约符合性 | @dev4 |
| Deployment | Docker/K8s/SSL 配置进度 | @dev5 |

**状态更新规则**:
- ⏳ → 🔄: 开始实现
- 🔄 → ✅: 实现完成并通过测试
- 🔄 → ⚠️: 实现中有风险
- ⏳ → ❌: 任务取消

---

### 3. 设计偏差识别（15 分钟）

**负责人**: 架构师

识别实现与设计文档的偏差：

#### 偏差分类

| 级别 | 说明 | 处理方式 |
|------|------|----------|
| 🔴 严重 | 实现与设计严重不符，影响功能 | 立即修复，暂停相关开发 |
| 🟡 中等 | 实现与设计有差异，但不影响核心功能 | 下周修复，记录技术债务 |
| 🟢 轻微 | 实现细节与设计有差异 | 可选修复，记录即可 |

#### 偏差记录模板

```markdown
### 偏差 #1

**模块**: WebSocket
**设计**: BACKEND-v3.2-WEBSOCKET.md#3.1
**偏差描述**: 心跳间隔实现为 60s，设计为 30s
**级别**: 🔴 严重
**影响**: 重连延迟增加，用户体验下降
**处理方案**: 修改为 30s，下周完成
**负责人**: @dev1
**截止日期**: 2026-04-17
```

---

### 4. 风险项跟踪（10 分钟）

**负责人**: 项目经理

跟踪上周识别的风险项：

| 风险项 | 级别 | 状态 | 处理方案 |
|--------|------|------|----------|
| tree-sitter 升级兼容性 | 🔴 | 已解决 | 测试通过 |
| WebSocket 性能不达标 | 🟡 | 进行中 | 优化中 |
| ... | ... | ... | ... |

---

### 5. 下周计划确认（10 分钟）

**负责人**: 项目经理

确认下周开发计划：

1. 优先级调整
2. 任务分配
3. 里程碑检查

---
