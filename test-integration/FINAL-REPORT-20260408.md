### Scene 3: 错误处理 ✅ PASSED

**测试内容**: 验证各种错误场景的处理

| 测试场景           | 状态 | 结果                     |
| ------------------ | ---- | ------------------------ |
| 后端不可用         | ✅   | 返回 `unavailable` 状态  |
| 无效 memory_id     | ✅   | 返回 404 + "记忆不存在"  |
| 缺少 content       | ✅   | 返回 422 (Pydantic 标准) |
| 缺少 abstract      | ✅   | 后端接受（可选字段）     |
| 无效 relation_type | ✅   | 返回 400 + 有效值列表    |
| 无效 tenant_id     | ✅   | 优雅处理                 |
| 网络超时           | ✅   | 正确处理                 |

**HTTP 状态码说明**:

- 后端使用 422 (Unprocessable Entity) 替代 400 (Bad Request)
- 这是 Pydantic/FastAPI 的标准行为
- 建议插件端统一处理 422 和 400
