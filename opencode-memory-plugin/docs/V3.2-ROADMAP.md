## 1. 版本概述

### 1.1 版本目标

v3.2 是一次 **架构升级** 版本，核心目标是：

1. **WebSocket 可靠化** — 从基础版升级到生产级（心跳、ACK、DIFF 模式）
2. **代码分析服务化** — 重构为 PrecomputeService，支持批量处理和增量更新
3. **数据库升级** — SurrealDB 3.0 + Meilisearch 0.40
4. **端口迁移** — 17999 → 18008，新旧服务隔离
5. **四层架构落地** — Atom/Entity/Relation/Timeline 模型完整实现

### 1.2 技术决策

| 决策        | 选择                     | 理由                               |
| ----------- | ------------------------ | ---------------------------------- |
| 多租户策略  | 单租户 + tenant_id 预留  | SDK 2.0 alpha 不稳定，延后物理隔离 |
| 架构保留    | 保留 v2.0 四层模型       | Atom/Entity/Relation 全部需要      |
| 代码分析    | PrecomputeService 服务化 | 从插件内置升级为后端服务           |
| 接口模式    | 插件工具 + CLI           | 无 MCP、无 IDE 集成                |
| SurrealDB   | 3.0+                     | RELATE、COMPUTED、FULLTEXT 特性    |
| tree-sitter | Query API                | 验证通过，性能提升 3.32x           |

### 1.3 风险评估

| 风险                 | 等级 | 缓解措施                               |
| -------------------- | ---- | -------------------------------------- |
| SurrealDB 3.0 兼容性 | 中   | 充分测试 RELATE 语法                   |
| WebSocket 复杂度     | 中   | 分阶段实现（基础 → 心跳 → ACK → DIFF） |
| 数据迁移丢失         | 低   | 双写过渡 + 全量备份                    |
| 依赖版本冲突         | 低   | 版本锁定（DEPENDENCY-VERSIONS.md）     |

#### Phase 2.2: 心跳机制（1 天）

- 30s 心跳间隔
- 2 次未响应触发重连
- 服务端 pong 处理

```javascript
// 心跳实现
startHeartbeat() {
  this.heartbeatTimer = setInterval(() => {
    if (this.missedPongs >= this.maxMissedPongs) {
      this.ws.close();
      return;
    }
    this.ws.send(JSON.stringify({
      type: 'ping',
      timestamp: Date.now(),
    }));
    this.missedPongs++;
  }, 30000);
}
```

#### Phase 2.3: 指数退避重连（1 天）

- 重连延迟：1s → 2s → 4s → ... → 300s（最大）
- 最大重试次数：10
- 重连成功后重置计数器

```javascript
scheduleReconnect() {
  if (this.retryCount >= this.maxRetries) {
    console.error('Max retries exceeded');
    return;
  }
  const delay = Math.min(
    this.baseDelay * Math.pow(2, this.retryCount),
    this.maxDelay
  );
  this.retryCount++;
  setTimeout(() => this.connect(), delay);
}
```

## 4. WebSocket 客户端实现

### 4.1 架构设计

```
┌─────────────────────────────────────────────────┐
│           ReliableWebSocketClient               │
├─────────────────────────────────────────────────┤
│                                                  │
│  ┌──────────────┐  ┌──────────────┐             │
│  │  Connection   │  │  Heartbeat   │             │
│  │  Manager      │  │  Manager     │             │
│  │              │  │              │             │
│  │ • connect()  │  │ • ping/pong  │             │
│  │ • close()    │  │ • 30s interval│             │
│  │ • reconnect  │  │ • 2 misses   │             │
│  └──────┬───────┘  └──────┬───────┘             │
│         │                  │                     │
│  ┌──────┴──────────────────┴───────┐             │
│  │         Message Handler          │             │
│  │                                  │             │
│  │  • send(data)                    │             │
│  │  • onMessage(callback)           │             │
│  │  • ACK tracking                  │             │
│  └──────────────────────────────────┘             │
│                                                  │
│  ┌──────────────────────────────────┐             │
│  │        Persistent Queue          │             │
│  │  • 离线消息持久化                  │             │
│  │  • 7 天过期清理                   │             │
│  └──────────────────────────────────┘             │
│                                                  │
└─────────────────────────────────────────────────┘
```

### 4.2 消息协议

**客户端 → 服务端**：

```json
// 心跳
{ "type": "ping", "timestamp": 1712721600000 }

// ACK 确认
{ "type": "ack", "seq": 42, "timestamp": 1712721600000 }

// 订阅
{ "type": "subscribe", "channels": ["entity_changes"], "session_id": "sess_abc" }
```

**服务端 → 客户端**：

```json
// 心跳响应
{ "type": "pong", "timestamp": 1712721600000 }

// 实体变更通知
{
  "type": "entity_change",
  "entity_id": "01HN...",
  "action": "created",
  "timestamp": "2026-04-10T12:00:00.000Z",
  "seq": 42,
  "diff": { "abstract": "new value" }
}

// 同步完成
{ "type": "sync_complete", "count": 15, "timestamp": "..." }
```

### 4.3 错误处理

| 错误代码 | 说明             | 处理策略                |
| -------- | ---------------- | ----------------------- |
| CONN_001 | 连接失败         | 自动重试 + 指数退避     |
| CONN_002 | 服务不可用       | 切换到备份端点          |
| MSG_001  | 消息发送超时     | ACK 超时 + 重试（3 次） |
| MSG_002  | 消息格式错误     | 验证 + 拒绝             |
| AUTH_001 | API 密钥无效     | 提示用户检查配置        |
| RECN_001 | 达到最大重试次数 | 降级模式（本地离线）    |

### 4.4 降级策略

```
WebSocket 连接
    │
    ├─ 正常 → 实时同步
    │
    ├─ 断线 → 离线队列 + 定时重连
    │         ↓
    │     重连成功 → 同步离线期间的消息
    │
    └─ 重连失败（10次）→ 降级模式
                          ↓
                     禁用实时同步
                     使用 HTTP 轮询（fallback）
                     用户提示：WebSocket 不可用
```

## 5. PrecomputeService 集成

### 5.1 数据流

```
File Save Event
    │
    ▼
Plugin (code-analysis-service.js)
    │
    ├─ 后端可用 → POST /api/v1/precompute
    │                │
    │                ▼
    │            PrecomputeService
    │                │
    │                ├─ tree-sitter AST 解析
    │                ├─ 符号提取
    │                ├─ 关系提取
    │                ├─ 批量写入 SurrealDB
    │                └─ 更新 Meilisearch 索引
    │
    └─ 后端不可用 → 本地 code-analyzer.js（降级）
                     │
                     └─ Oxc / tree-sitter 本地分析
```

### 5.2 API 接口

```javascript
// 插件调用 PrecomputeService
async function analyzeWithPrecompute(filePath, content, language) {
  const response = await fetch('http://localhost:18008/api/v1/precompute', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      WRAPPER_MEILI_API_KEY: apiKey,
    },
    body: JSON.stringify({
      file_path: filePath,
      content: content,
      language: language,
      project_id: getProjectId(),
    }),
  });

  return response.json();
}
```
