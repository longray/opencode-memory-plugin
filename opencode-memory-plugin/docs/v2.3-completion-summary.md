## 核心功能实现

### 1. 双模式同步 (P1 + P2)

#### Checkpoint 文件管理
- **功能**: `loadCheckpoint()`, `updateCheckpoint()`, `getCheckpointHistory()`
- **存储**: `.sync/checkpoint.jsonl` (JSONL 格式)
- **内容**: 时间戳、操作类型、文件变更数、条目统计、错误日志

#### 文件变更检测
- **算法**: SHA256 哈希对比 + 修改时间检查
- **检测类型**: 新增、修改、删除、未变更
- **扫描范围**: `timeline/` + `active/` 目录

#### 增量同步
- **工具**: `incremental_sync` (支持 dry_run 模式)
- **逻辑**: 只上传变更文件
- **统计**: 上传数、更新数、失败数、删除数

#### 全量同步
- **工具**: `full_sync` (支持断点续传)
- **功能**: 
  - 流式扫描所有文件
  - 对比本地与后端索引
  - 批量处理 (batchSize=50)
  - 进度持久化 (`progress.json`)
  - 自动冲突裁决

### 2. 冲突解决框架 (P3)

#### 冲突检测
- **函数**: `detectConflict()`
- **类型**: 同时修改(simultaneous) / 顺序修改(sequential)
- **指标**: 时间差、相似度、新旧判断

#### 相似度计算
- **函数**: `calculateSimilarity()`
- **算法**: 内容长度比率 + 共同词汇
- **阈值**: >0.9 建议合并

#### 质量评估
- **函数**: `assessQuality()`
- **维度**: 
  - 完整性 (标签、项目ID、类型)
  - 信息密度 (词汇数)
  - 内容长度
  - 来源可靠性

#### 自动裁决策略
```javascript
策略1: 时间戳裁决 (顺序修改)
策略2: 内容质量评估 (质量差异 >0.3)
策略3: 相似度合并 (相似度 >0.9)
回退: 需要人工决策 (MANUAL)
```

### 3. 用户决策界面 (P4)

#### 新增工具
- `incremental_sync` - 增量同步
- `full_sync` - 全量同步（支持 resume/auto_resolve）
- `conflict_list` - 列出未解决冲突
- `conflict_resolve` - 解决单个冲突
- `batch_resolve` - 批量解决冲突
- `sync_checkpoint` - 查看同步历史

#### 冲突报告
- **函数**: `generateConflictReport()`
- **内容**: ID、类型、文件、本地/后端预览、建议、相似度

#### 解决操作
- `USE_LOCAL` - 使用本地版本
- `USE_BACKEND` - 使用后端版本  
- `MERGE` - 合并两个版本
