## Context

当前知识图谱存在三个关键质量问题：

1. **对话知识实体严重不足**：仅3个decision/solution/pattern实体，技术决策、问题解决方案、代码模式等知识缺失
2. **关系权重不均**：部分关系权重为0.7，缺乏基于调用频率和依赖强度的动态权重计算
3. **中文搜索薄弱**：中文关键词搜索无结果，BM25分词对中文支持不足

当前状态：

- 实体数：103个（code_module 46个, code_function 39个, code_class 18个）
- 关系数：69个（主要为contains关系）
- 主题数：103个
- 中文搜索准确率：<50%

## Goals / Non-Goals

**Goals:**

- 从历史会话中提取技术决策、方案、模式，创建20-30个对话知识实体
- 优化关系权重计算（基于调用频率、依赖强度），权重范围0.3-1.0
- 增强BM25中文分词，支持Bigram和字符级分词
- 建立关系验证机制，检测孤立实体和缺失关系
- 生成知识质量报告（实体分布、关系网络、搜索质量）

**Non-Goals:**

- 不修改现有代码实体（仅优化关系和补充对话知识）
- 不删除已有实体和关系
- 不修改Entity-Atom架构
- 不实现实时权重更新（本次为一次性优化）

## Decisions

### 决策 1：会话知识提取策略

**选择**：使用session_search提取技术决策信号词（"我决定..."、"选择X因为..."、"根因是..."）

**理由**：

- 信号词模式准确识别技术决策
- 避免全量扫描，提高效率
- 可配置信号词列表，灵活扩展

**替代方案**：

- 全量会话扫描：效率低，噪音大
- 手动标注：成本高，不可扩展

### 决策 2：关系权重计算模型

**选择**：权重 = 基础权重(0.5) + 调用频率系数(0.3) + 依赖强度系数(0.2)

**权重范围**：0.3（弱关系）- 1.0（强关系）

**理由**：

- 综合考虑静态依赖和动态调用
- 避免权重过于集中（当前多为0.7）
- 可解释性强

**替代方案**：

- PageRank算法：复杂度高，需要迭代计算
- 机器学习模型：需要训练数据，过拟合风险

### 决策 3：中文分词优化方案

**选择**：Bigram分词 + 字符级分词混合

**实现**：

- 中文文本：使用Bigram（"知识图谱"→"知识"、"识图"、"图谱"）
- 混合文本：保留英文单词，中文部分Bigram
- 停用词过滤：去除"的"、"了"、"是"等

**理由**：

- Bigram适合中文语义匹配
- 字符级分词作为fallback
- 与现有BM25集成简单

**替代方案**：

- 引入jieba分词：增加依赖，复杂度高
- 神经网络分词：需要训练，性能开销大

### 决策 4：关系验证策略

**选择**：三级验证：孤立实体检测 → 关系完整性检查 → 权重合理性验证

**验证规则**：

- 孤立实体：无入边且无出边的实体
- 缺失关系：code_class应有contains关系指向其方法
- 权重异常：权重<0.3或>1.0的关系

**理由**：

- 分层验证，定位问题精准
- 可自动化执行
- 生成可操作的修复建议

## Risks / Trade-offs

| 风险             | 影响 | 缓解措施                  |
| ---------------- | ---- | ------------------------- |
| 会话提取噪音     | 中   | 信号词过滤 + 人工审核阈值 |
| 权重计算不准确   | 低   | 多维度加权 + 可手动调整   |
| 中文分词效果不佳 | 中   | A/B测试 + 迭代优化        |
| 关系验证误报     | 低   | 配置白名单 + 人工确认     |

**Trade-offs**：

- **自动化 vs 准确性**：自动提取 + 人工审核关键决策
- **覆盖率 vs 精准度**：优先精准度，宁可漏提不误提

## Migration Plan

### Phase 1: 会话知识提取（1小时）

1. 使用session_search搜索决策信号词
2. 使用session_read提取会话内容
3. 识别技术决策、方案、模式
4. 创建decision/solution/pattern实体（20-30个）
5. 验证实体质量

### Phase 2: 关系权重优化（30分钟）

1. 分析现有69个关系的权重分布
2. 重新计算权重（调用频率 + 依赖强度）
3. 更新关系权重
4. 验证权重合理性

### Phase 3: 中文搜索增强（30分钟）

1. 分析BM25分词逻辑
2. 添加中文Bigram分词支持
3. 测试中文搜索准确率
4. 优化停用词过滤

### Phase 4: 关系验证（20分钟）

1. 检测孤立实体
2. 检查关系完整性
3. 验证权重合理性
4. 生成修复建议

### Phase 5: 质量报告（20分钟）

1. 生成实体分布报告
2. 生成关系网络报告
3. 生成搜索质量报告
4. 生成优化建议

### Rollback Strategy

- 备份现有关系权重
- 保留原始BM25分词逻辑
- 可单独回滚各阶段优化
